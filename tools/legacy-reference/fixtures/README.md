# Golden fixture format

`goldens.json` is generated by `../generate_goldens.py` from AST-extracted
definitions in the legacy Python source. Do not hand-edit expected values.
Regenerate and run `--check` when the reference source or extraction changes.

## Top-level keys

| Key | Meaning |
| --- | --- |
| `schema` | Fixture schema version (`1`) |
| `generated_by` | Script path, for provenance |
| `reference` | Extraction and network-guard description |
| `runtime` | Python and pymongo/bson versions used to generate |
| `provenance` | Per-file source SHA-256 and per-block line range/block SHA-256 |
| `fixtures` | The expected values consumed by C# tests |

## `fixtures.filename`

`cases[]` has `input`, `folder`, and either:

- `ok: true`, `prefix`, `suffix`, `file_type`, `sort_name`; or
- `ok: false`, `error: {type, message}`.

`file_type`: `0` unknown, `1` folder, `2` image, `3` text. `sort_width` is `6`.

## `fixtures.labelplus_load`

`input` is the exact LabelPlus text. `expected[]` is the original Python result:
`{file_name, labels[{x, y, position_type, translation}]}`. It covers two
files, three labels, multiline text, an empty translation, and Unicode/emoji/
HTML specials.

## `fixtures.labelplus_export`

`plain`, `staff_first`, `staff_last`, and `export_name` are exact Python
`File.to_labelplus` outputs (CRLF line endings). `file` records the synthetic
name/ancestor inputs. `staff_block` is the injected staff block.

## `fixtures.notification`

- `valid[]`: `{input, ok: true, nodes}` with the exact `parse_body` tree.
- `invalid[]`: `{input, ok: false, error: {type, message, status_code}}`.
- `safe_url[]`: `{input, expected}` for `safe_url`.
- `normalize`: `{input, expected, tokens}` from `normalize`/`search_tokens`.
- `project_access[]`: `{case, expected}` for `project_accessible`; the
  callback is a fixed fixture scope (`allowed`, `denied`, `banned`, missing
  project/user, and `DoesNotExist`).

## `fixtures.file_order`

`project_call` is the exact call made by `order_snapshot`
(`parent=None`, `type_only=2`). `files[]` gives IDs/names/manual order.
`canonical_json` is `json.dumps(..., ensure_ascii=False)` with Python's default
`, ` separator. `version` and `json_sha256` are SHA-256 of its UTF-8 bytes.
`export_with_manual` and `export_without_manual` are `export_file_names`
results.

## `fixtures.label_snapshot`

- `metadata`: deterministic fields from the inserted snapshot metadata
  (`name`, `version`, `reason`, `ready`, `digest`, `counts`, `revision`).
- `chunk_bytes_override`: `200` was used instead of the production
  `CHUNK_BYTES=4*1024*1024` to force multiple chunks in a small fixture. The
  chunking code is still the original extracted `create_snapshot`.
- `chunk_count` and `chunks[]`: each chunk has `index`, `kind`, `byte_length`,
  `sha256`, `stored_hash`, `b64`, and sanitized `rows`.
- `row_bson`: per-kind row bytes as `b64`, `sha256`, `byte_length`,
  `field_order`, and `field_types`.

`metadata.digest` is the original `data_digest` over the typed rows.
`chunks[].sha256` is SHA-256 of the raw BSON `{rows: [...]}` payload, and
`stored_hash` is the hash written by `create_snapshot` (they must match).

The sanitized JSON representation uses `$oid`, `$int64`, `$decimal128`,
`$date`, and `$binary` markers for values that are not native JSON. Use the
base64 bytes for exact BSON comparison.

## `fixtures.bson_typed`

`cases[]` contains standalone BSON documents with `field_order`, top-level
`field_types`, `b64`, `hex`, `sha256`, and a sanitized `decoded` view. Cases
cover an ordered mixed document and scalar/nested types. These are suitable
for checking a C# BSON writer or comparator without involving Mongo.

## Consuming from C#

1. Parse the JSON with `System.Text.Json`.
2. Decode `b64` with `Convert.FromBase64String`.
3. Compare raw bytes first, then `SHA256.HashData`.
4. For object values, compare canonical BSON bytes or field order explicitly;
   do not compare the sanitized `decoded` JSON as if it were BSON.
5. Treat `chunk_bytes_override` as fixture-only and do not use it as the
   production chunk size.

## Provenance and limits

`provenance[]` records the original relative path, source-file SHA-256, and
each block's line range/source SHA-256. The JSON was produced by the original
functions, but some dependencies were deliberately stubbed:

- `gettext` is identity for `Filename`.
- `project_accessible` uses a fixed callback scope, not the production RBAC
  database.
- `create_snapshot` uses in-memory fake snapshot/chunk collections and a fake
  `label_data`; the BSON/digest/chunk algorithm is original, but persistence is
  not exercised.
- `File.to_labelplus` uses synthetic sources/translations; it does not query a
  database.
- No original Flask app, config, dotenv, conftest, tests, storage, or network
  was used. See `../../../docs/reference-validation.md` for the full assessment.
